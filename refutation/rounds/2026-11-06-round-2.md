# Refutation round 2 — slot engine

Date: 2026-11-06

Rounds allowed: 3 · Round: 2 of 3
Graduation rule (signed before the round): every clause has a passing test,

The refuting agent received the contract and the ability to call

## Candidates raised

### R1

```
CLAUSE:   C3 / C5
INPUT:    resolveSlot([{ id:'r', openHours:[{start:540,end:1020}],
                         booked:[{start:540,end:600}] }],      // no turnaroundMinutes
                      { durationMinutes: 30 })
EXPECTED: a slot at or after 10:00 (9:00–10:00 is booked), or a typed rejection
OBSERVED: { ok: true, slot: { start: 540, end: 570 } }   — 9:00, over the booking
SEVERITY: HIGH
```

**Triage: real violation, and the worst kind.** With `turnaroundMinutes`
absent, `b.end + undefined` is `NaN`; `NaN` never overlaps anything, so every
reservation on that resource silently disappeared from the collision check.
The contract's typedef said the field was required, but nothing enforced it,
and the engine answered confidently with a time that was already taken. The
model would have rendered that confirmation.

Fixed by **adding C9** (malformed resources fail closed, `INVALID_RESOURCE`),
test first, then the guard. Mutant `M8` reintroduces the tolerance permanently.

### R2

```
CLAUSE:   C3
INPUT:    resolveSlot([{ id:'r', openHours:[{start:540,end:660}],
                         booked:[{start:600,end:660}], turnaroundMinutes:15 }],
                      { durationMinutes: 60 })
EXPECTED: rejection — a 9:00–10:00 slot leaves no 15-minute turnaround before
          the 10:00 reservation
OBSERVED: { ok: true, slot: { start: 540, end: 600 } }
SEVERITY: MEDIUM
```

**Triage: contract ambiguity that hid a real defect.** C3 as written covered
only the trailing buffer of *existing* reservations. The behaviour matched the
letter of the clause and still produced a schedule with no turnaround. Resolved
by **amending C3** to make the buffer symmetric (the proposed slot carries the
same trailing buffer), adding the test, and encoding the defect as `M7`.

### R3

```
CLAUSE:   C8
INPUT:    resolveSlot([r1, r2], { durationMinutes: 30, resourceIds: 'r1' })
EXPECTED: rejection — the filter is not an array
OBSERVED: { ok: true, slot on r1 }  — 'r1'.includes(id) matched by substring
SEVERITY: MEDIUM
```

**Triage: real violation of the spirit of C8, not covered by its letter.**
A string filter was accepted and `String.prototype.includes` turned the
resource filter into a substring match. Folded into **C9** with its own test and
mutant `M9`.

### R4

```
CLAUSE:   C8
INPUT:    { durationMinutes: 30, notBefore: -5 }   and   { notBefore: 570.5 }
EXPECTED: unclear — C8 only names duration and inverted windows
OBSERVED: accepted; clamped to open hours / produced a slot at 9:30
SEVERITY: LOW
```

**Triage: noise, logged.** Negative and fractional window bounds are clamped by
open hours and cannot produce a colliding or out-of-window slot. Left as is;
if a future round shows a user-visible effect it becomes a clause.

### R5 (found by CI, after the round)

```
CLAUSE:   none — harness itself
INPUT:    npm test on Node 20
EXPECTED: 20 tests run
OBSERVED: Could not find 'tests/*.test.js' — Node 20 does not expand a quoted glob
SEVERITY: MEDIUM (the README promised Node >= 20; on 20 neither tests nor mutation ran)
```

**Triage: real defect in the harness, not the engine.** Fixed by using the
test runner's default patterns. The CI matrix (20 and 22) exists so this class
cannot return.

## Outcome

- 1 HIGH and 2 MEDIUM violations fixed, each with a test written before the fix.
- Contract: C3 amended, C9 added (8 → 9 clauses).
- Mutants: 6 → 9, all killed.
- New check `npm run trace`: every clause has a test and every test and mutant
  names a real clause — the README's traceability claim is now executable.
- Randomized invariant test for C1 (seeded, 400 cases) added as a net under
  the hand-written cases.

**Graduated** under the pre-signed rule, in round 2 of 3.

## Note

R1 is the lesson of the whole repository in one line: the defect was in
deterministic code, it was invisible to the model, and it would have been
reported as "the bot gave me a taken slot" — an LLM bug that was never an LLM
bug.
